# 5-Minute Demo Guide

## 0:00–0:30 — The problem

Explain that legal work is not one chat. The same Matter can accumulate documents, research, decisions, actions, revisions, and collaborators over days or months.

## 0:30–1:20 — Start a Matter naturally

1. Start a new chat.
2. Upload a contract or legal document.
3. Ask a plain-language question such as “帮我站在买方角度看看这份合同，优先找真正会卡交易的地方。”
4. Show that the user is not forced through a large intake form before useful work starts.

## 1:20–2:00 — Evidence friction reduction

Open one legal citation.

Show the chain:

`answer` → `citation` → `authorized source` → `exact passage / locator`.

Explain that the model is not expected to invent a URL or pinpoint.

## 2:00–2:50 — Work product as a live object

1. Open a generated work-product card inside the app.
2. Show its revision/family status.
3. Select one bounded block.
4. Ask: “这一段改得更适合给客户看，保留结论但降低确定性。”
5. Show that only the bounded target is rewritten and a child revision is created.

## 2:50–3:40 — Matter continuity

Open the Matter:

- Chats;
- Documents and versions;
- Work Product;
- People & Access.

Explain that one Matter can have several chats without losing the same evidence/document/work-product context.

## 3:40–4:20 — Collaboration and privacy

Invite or show role presets:

- trainee;
- supervisor;
- client reviewer (sanitized-only).

Explain that sharing a chat is not the same as granting access to a Matter.

## 4:20–5:00 — Why this is different

Show the architecture diagram and summarize three differentiators:

1. proposition-level evidence / authority discipline;
2. professional work product + revision lineage;
3. Matter-scoped collaboration and permissions.

If a live external provider is unavailable, do not fake a result. Use an existing fixture/screenshot and state which integration remains pending live validation.
